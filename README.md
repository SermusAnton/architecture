# Project

## Техническое задание
Существует игровой сервис Космической игры. Игрок принимает участие в игре посредством программы, которая загружается в специальное приложение Агент.
В процессе игры возникает необходимость администратору состязания "online" применить для всех участников новые правила игры. 
Например: Движение возможно только с расходом топлива. У корабля есть некоторый начальный запас топлива. Запас топлива проверяется перед началом движения.
С реализацией такого сценария возникают 2 проблемы:
1. Внутреннее устройство сервиса представляет собой очередь выполняемых команд. Команды разработаны на Java. Требуется перезапуск сервиса для инициализации новых типов команд, реализующие новые правила. Остановка игры негативно влияет на соревновательный процесс.
2. Правила при необходимости применяет администратор игры. Требуется гибкий, самодокументируемый, но в то же время простой механизм применения правил.

Для решения 1 проблемы предлагается использовать механизм динамической загрузки. Логика правил реализована в классах Java с интерфейсом Command.
Несколько правил могут быть объединены посредством MacroCommand. Существует возможность дополнительной обработки при возникновении ошибок.
В таком виде команды, макрокоманды, прерывания и простые значения заранее подготавливает разработчик и располагает в зависимом модуле проекта.
Это позволяет быстро интегрироваться с уже существующей системой, подготовить отдельный загружаемый jar-файл. В библиотеку включен класс регистрирующий новые команды в игровом сервисе.
Игровой сервис содержит команду, которая загружает библиотеку в память, используя URLClassLoader, запускает процесс регистрации возможных действий в IoC выполняя метод init интерфейса Register.

Для решения 2 проблемы: простого и гибкого механизма применения правил игры предлагается разработать и внедрить DSL правил игры на русском языке.
Например: Корабль умеет Движение, Поворот, Выстрел. Движение включает Проверка топлива, Move, Сжигание топлива. Поскольку грамматика простая, то было принято решение
не использовать сторонние парсеры и анализиторы, а разработать свое решение. Парсер (Parser.class) разбирает последовательность строк.
Интерпретатор регистрирует (RuleConfigurator.class) соответcтвующие команды в сервисе игры.
